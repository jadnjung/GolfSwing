# Supported device matrix

Phase 0 deliverable (`docs/PRD.md` section 16) and the category structure PRD section 13.4's physical-device test matrix expects. This defines _what counts as in-scope_ and _why_, grounded in what's actually configured in `apps/mobile` today. It is **not** a substitute for PRD 13.4's requirement to test on real physical hardware — "camera and ML validation cannot rely only on emulators or simulators" — which this agent cannot do without physical devices. Selecting and acquiring the actual test devices below is still a team action item, not something this document completes.

## Minimum OS versions (already configured, not proposed)

| Platform | Minimum                     | Where it's set                                                         | Source                                                                                                                                                                                                        |
| -------- | --------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| iOS      | 15.1                        | `apps/mobile/ios/Podfile` (`platform :ios, min_ios_version_supported`) | React Native 0.81.6's own `Helpers::Constants.min_ios_version_supported` (`node_modules/react-native/scripts/cocoapods/helpers.rb`) — inherited from the RN version pin (ADR 0003), not chosen independently. |
| Android  | API 24 (Android 7.0 Nougat) | `apps/mobile/android/build.gradle` (`minSdkVersion`)                   | React Native 0.81.6's own Gradle version catalog, resolved during Step 2 (`docs/adr/0003-react-native-version.md`).                                                                                           |

These aren't a product decision this document is making — they're a direct consequence of the React Native version already pinned. Lowering them would mean fighting the framework's own minimum; raising them is a real option (PRD section 22, item 2: "Minimum supported Android API level" is still an open product decision) if the team wants to narrow the device matrix further, e.g. to exclude devices too old to realistically run on-device pose inference well regardless of what OS they can technically boot.

## Camera capability tiers this app cares about

PRD section 5.1 (CAM-003/CAM-004/CAM-005) means device selection isn't just "does it run the app" — it's "which camera capability tier does it fall into," since behavior deliberately changes per tier rather than failing:

1. **Single-camera baseline** — every supported device must work here; this is the only tier PRD 3.1 (MVP scope) actually requires.
2. **Concurrent front+rear capture** — iOS via `AVCaptureMultiCamSession` (Apple's public documentation ties this to the A12 Bionic chip and later, i.e. iPhone XS/XR-generation devices and newer — stated here as the publicly documented starting point, not independently verified against a real device in this environment); Android via CameraX concurrent camera selection, support varies by OEM/chipset and must be queried at runtime (PRD CAM-003 already requires a runtime capability check, not a hardcoded device list).
3. **High frame rate (60/120 FPS) at a usable resolution** — varies by device and by the specific resolution requested; PRD CAM-005's own priority order (120 → 60 → 30 FPS) already assumes graceful degradation per device, which is real code (`useCameraFormat`/format querying) still open per `Checklist.md` ("Frame rate is a UI selector only, not yet wired to an actual device format/fps query").

## Proposed physical test tiers (PRD 13.4's categories, not yet acquired/tested)

| Tier                                             | iOS                                                                                                                                                                                                                                                   | Android                                                                                                                                                      |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Oldest supported                                 | Oldest iPhone still receiving the current iOS major version at/above 15.1                                                                                                                                                                             | A real device at or near API 24, not just an emulator image — OEM camera stacks vary meaningfully from AOSP's reference behavior                             |
| Midrange                                         | A current-generation mid-tier iPhone (e.g. the non-Pro line)                                                                                                                                                                                          | A midrange Samsung (PRD 13.4 names Samsung specifically)                                                                                                     |
| Flagship                                         | Current-generation iPhone Pro/Pro Max                                                                                                                                                                                                                 | Current-generation Samsung flagship, and a Google Pixel (PRD 13.4 names both)                                                                                |
| Multi-cam capable                                | An iPhone confirmed via `AVCaptureMultiCamSession.isMultiCamSupported` on real hardware (publicly documented as requiring roughly A12-generation chips or newer — not independently verified here, and not something to hardcode instead of checking) | A device whose CameraX `isConcurrentCameraModeSupported` check actually returns true — OEM-dependent, must be verified per-device, not inferred              |
| Multi-cam _unsupported_ (graceful fallback path) | Any older supported iPhone below the multi-cam boundary                                                                                                                                                                                               | Any Android device where the CameraX check returns false                                                                                                     |
| Lower-memory                                     | —                                                                                                                                                                                                                                                     | An explicitly lower-RAM Android device (PRD 13.4) — pose inference and video encoding running concurrently is where memory pressure will show up first       |
| OS version spread                                | At least two iOS majors within the supported range                                                                                                                                                                                                    | At least two Android OS versions within the supported range (PRD 13.4) — OEM camera behavior differences often correlate with OS version, not just API level |

## What this document does not do

- **Does not name specific device models as "confirmed supported."** Every capability claim above that depends on real hardware behavior (multi-cam support, frame-rate/format availability, memory headroom under concurrent camera+inference load) is explicitly a runtime check per PRD CAM-003/CAM-004, not something to hardcode from a spec sheet.
- **Does not replace PRD 8.4's model-evaluation device requirements** (phone generations, Android manufacturers, camera height/distance variation) — that's a pose-model evaluation dataset concern (`docs/adr/0009-defer-pose-inference-library.md`), broader than which physical units QA owns for camera/build testing.
- **Does not set the minimum Android API level as a final product decision** — PRD section 22 still lists this open; API 24 above is simply what the current RN pin defaults to, not a chosen floor.
